- 目录：`assets/reference/<资产ID>/` 存参考图，`assets/meshy/raw/<资产ID>/` 存 Meshy 原始导出（以上二进制文件默认不纳入版本管理，只保留 README 与校验值），`public/assets/models/<类别>/` 存优化后的 GLB。

## 总则
- **付费调用须事先授权**：每次调用 Meshy 或其他付费生成服务（包括用 codex-cli 生成参考图），都要经用户明确授权；授权写明资产、次数上限和积分上限。超出上限须重新授权。
- **可追溯**：每次生成都登记任务 ID、日期、模型版本、参数、积分和产出文件。失败或废弃的尝试同样登记，原始文件不删除。
- **以现行条款为准**：Meshy 的生成模式、参数、价格、许可与绑骨/动画能力，每次生成前都核对官方文档和价格页；本文不写死具体数值。
- **独立来源**：禁止引用、复制或参照 Aholo Forest Moments 的模型、贴图或参考图。
- **密钥**：Meshy 密钥只从本机用户级环境变量 `MESHY_API_KEY` 读取（已配置，2026-11-09 确认存在，未读取其值）。只能由本地生成脚本使用，不写入仓库文件、命令行参数、日志或清单；不得改名为 `VITE_` 前缀，也不得在前端代码中引用，以免被打包进静态站点。

## 流程

状态流转：`规划` → `参考就绪` → `已生成` → `验收通过`（不通过则 `退回`）→ `已优化` → `已集成` → `可用`；弃用的资产标为 `退役`。

### 1. 风格确认
- 输入：`docs/ART_DIRECTION.md`（Master Prompt v1、单资产要求、角色规范、Negative Prompt）。
- 产出：在清单中写资产简介，包括用途、区域、类别、优先级、尺寸目标、面数与贴图预算，以及特殊需求（发光、动画、交互）。
- 门槛：简介只使用既定风格词汇；需要新风格元素时先修改美术方向并经用户确认。
- 状态：`规划`。

### 2. 参考图
- 来源：用户提供，或经授权用 codex-cli 生成。生成时记录提示词全文、日期和账号类型。
- 要求：单一主体、中性浅灰背景、无文字水印；角色为 A 字姿势，提供正、侧、背视图且各视图一致；道具与建筑至少提供正面和 3/4 视图。
- 检查：视图之间的配件位置、左右、比例必须一致，有冲突的先修正。
- 登记：文件名、视角、尺寸、SHA-256、来源和权利说明，写入 `assets/reference/<资产ID>/README.md` 与清单。
- 状态：`参考就绪`。

### 3. Meshy 模型生成（需授权）
- 模式选择：有多视图参考的优先用多图生成，单张参考用图生 3D；文本生成只用于探索，不作为正式产出。
- 参数：目标面数、拓扑类型、是否生成 PBR 贴图等，按清单预算设置并原样记录。
- 迭代：每个资产默认最多 3 次生成；超出须重新授权。
- 产出：原始导出（GLB/FBX 及贴图）放到 `assets/meshy/raw/<资产ID>/<任务ID>/`，同时登记任务 ID、积分和模型版本。
- 状态：`已生成`。

### 4. 视觉与结构验收
在 Blender 或查看器中逐项检查，结果写入清单的备注：

| 类别 | 检查项 |
| --- | --- |
| 视觉 | 剪影、配色、材质与参考图及 Master Prompt 一致；没有 Negative Prompt 列出的问题；在约 6.5 m 镜头距离下可读。 |
| 结构 | 无破洞、漂浮碎片和反面法线；比例、朝向可以修正；角色手指、兜帽、披肩与身体的分离和穿插可接受。 |
| 贴图 | 无明显接缝和烘焙光照；UV 可用；需要发光的部位能拆出 Emissive。 |
| 预算 | 面数和贴图能在 Blender 中优化到预算以内。 |

结论为 `验收通过` 或 `退回`。退回须注明原因和下一次生成要调整的参数。

### 5. Blender 优化
- 应用缩放，单位为米；Y 向上，原点在底部中心，正面朝 +Z（导出 glTF 后）。
- 按预算减面或重拓扑；需要时制作 LOD1（树木等大量实例的资产必做）。
- 合并材质，贴图按预算缩放；打包 ORM，命名统一用英文。
- 角色按 `docs/ANIMATION_PIPELINE.md` 处理骨架和 idle/walk/run 动作。
- 导出独立 GLB。网格压缩（meshopt/Draco）和 KTX2 贴图需要先扩展加载代码，在首个资产集成时实测后再决定。
- 优化后的源文件（.blend）不纳入版本管理，存放位置登记在清单中。
- 状态：`已优化`。

### 6. GLB 导入 Three.js
- 放入 `public/assets/models/<类别>/<资产ID>.glb`，经 `assetConfig.baseUrl` 加载。
- 树木用实例化；碰撞与镜头遮挡继续使用 `forestLayout.ts` 的代码代理，并按模型实际尺寸更新代理参数。
- 验证：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm test:e2e` 全部通过；把性能基线（帧时间、绘制调用、三角形数）与灰盒基线对比，写入 `PROGRESS.md`。
- 状态：`已集成`；用户在游戏内确认视觉后改为 `可用`。
